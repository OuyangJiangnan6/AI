# 拾光 · 购物任务助手

面向“赛题 02—搭建你理想中的购物助手”的可运行原型。用户用自然语言描述需求，助手在多轮对话中整理预算、品类、偏好与排除条件，给出预算内的组合方案和取舍说明。

> 本仓库中的商品、价格与评价均为虚构演示数据。当前版本不查询真实电商平台；可选模型只负责理解需求，默认使用本地解析。它用于展示可解释、可复现的购物决策流程。

## 在线展示与本地运行

本项目可以直接部署到 Streamlit Community Cloud：创建公开 GitHub 仓库后选择仓库、分支和 `app.py` 作为入口。部署前请检查平台当时的要求。也可以仅按下列步骤本地运行：

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

浏览器打开终端显示的本地地址，通常是 `http://localhost:8501`。

## 现场演示脚本

1. 输入“预算 1500 元，想买通勤降噪耳机”。
2. 下一轮输入“不要入耳，预算改为 900 元”，观察约束和推荐变化。
3. 清空任务，输入“预算 1200 元，买耳机和键盘，适合图书馆学习”，观察跨品类组合与预算结余。
4. 输入“预算 100 元，耳机和键盘”，观察不可行时的最低预算说明。

## 核心流程

```text
用户自然语言 → 提取品类/预算/偏好/排除条件
              → 跨轮维护购物任务
              → 枚举符合硬约束的商品组合
              → 按偏好覆盖和价格排序
              → 展示推荐依据与取舍
```

- **硬约束**：总预算、品类、排除特征。
- **软偏好**：降噪、无线、舒适、静音等。优先让方案覆盖更多偏好，再参考价格。
- **可解释性**：展示匹配与未匹配偏好、每件商品的优点和取舍。
- **可复现性**：内置 15 件虚构商品，无 API Key、账号或网络数据依赖。

## 设计边界与下一步

当前需求理解使用关键词规则，适合在现场稳定复现，但不能充分处理复杂口语、隐含意图和商品知识。真实产品需要接入授权商品数据、库存与价格更新、检索召回、评价证据及合规的跳转链路。可进一步用检索增强和大模型改善意图识别与解释生成，并以真实用户任务评估推荐质量。切勿把平台凭据、个人资料或真实用户对话提交到仓库。

## 参赛展示重点

本原型把“想买什么”转为可追踪的约束状态，并让用户通过后续话语修改任务。演示时建议重点解释：为什么某方案入选、为何另一方案被预算或排除条件淘汰、预算变化后结果如何调整。


## 可选模型理解

设置 SHOPPING_AI_BASE_URL（不含 /chat/completions）、SHOPPING_AI_API_KEY 和 SHOPPING_AI_MODEL 三个环境变量，然后启动应用，在侧栏启用模型理解。模型仅提取完整购物任务状态；商品筛选和预算约束仍由本地规划器执行。没有配置或模型请求失败时，会自动使用本地解析。请将密钥保存在本机环境变量或部署平台的密钥设置中，不要提交到仓库。

llm.py 提供兼容 chat/completions JSON 接口的可选适配层，tests/test_llm.py 验证模型结果校验逻辑。实际模型服务需要你提供可用的接口与密钥后再做端到端验证。
